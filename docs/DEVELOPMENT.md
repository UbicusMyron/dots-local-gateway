# 开发阶段与任务入口

Last Reviewed: 2026-10-15

当前已确认两个组件的职责和目录。开发沿以下阶段推进，每阶段依据前一阶段证据形成具体任务。

| 阶段 | 负责部分 | 输入 | 交付与完成条件 |
| --- | --- | --- | --- |
| 1. 最小连接验证 | 两端探针与现成通道 | 请求草案、目标账号和 Mac mini | 真实 dots 的工具调用、脚本三次自主请求、小文件内容核对及认证证据 |
| 2. 最小契约定案 | docs/CONTRACTS/ | 通道验证证据 | 确认认证位置、请求/响应结构、错误及文件形式，补齐精确验证命令 |
| 3. 网关实现 | macmini_gateway | 已确认契约 | 模拟客户端和模拟第三方验证凭证路由、目标校验、请求及下载 |
| 4. 调用端实现 | dots_request | 同一契约 | 模拟网关验证脚本调用、错误处理、文件保存及 skill 使用说明 |
| 5. 双端联合验收 | 两个组件 | 各组件验证结果 | 真实 dots 与 Mac mini 链路、两个独立业务样例、进程恢复证据 |
| 6. 首个平台接入 | 网关适配与客户端配置 | 平台、认证方式、读写范围和接入授权 | 代表性真实请求及文件交付证据 |

阶段 3 与阶段 4 可各自开展实现和测试，执行安排由当时任务确定。阶段 1 的轻量探针用于选择可行通道，正式客户端以验证结果为依据。

当前接续任务：[001 最小请求通道验证](TASKS/001-verify-transport.md)。用户已授权先行实现 macmini_gateway 的独立可验证部分，[003 网关本地只读核心](TASKS/003-gateway-core.md) 已完成模拟验证；正式服务接线及稳定契约依据阶段 1、2 的证据完成。本表记录阶段路线；每项实现任务在依赖条件齐备后补充触及文件、接口、验收和精确命令，再进入 Ready。

治理检查沿用 constitution 工具。SPEC 的 Delivery Scope 记录交付范围，Non-Goals 记录已确认的非目标；后者适用治理写作豁免，检查结果按实际运行记录。

2026-10-15 用户授权调用端实现：[002 dots_request 调用核心](TASKS/002-dots-request-core.md) 已完成本地模拟验收。当前 Python 注入边界用于适配器开发；正式通道、认证和文件线协议随阶段 1–2 定案。任务 001 保持待验证状态。
