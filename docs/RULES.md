# RULES

Last Reviewed: 2026-10-15

## Coding Rules

- 实现以当前交付范围为准，保持单一、轻量。
- 业务循环在 dots 执行；堡垒机处理结构化 API/下载请求。
- 文档正文采用正向表述，以职责、有效范围、前置条件和验收标准表达设计。治理章节 `Non-Goals` 的标题及范围排除说明豁免此写作规则，仅记录已确认的非目标。

## Testing Rules

- Required checks: 相关契约、模拟请求正常及异常路径、凭证隔离；传输阶段分别验证 AI 和脚本调用。
- Minimum coverage expectations: 覆盖关键边界；真实平台接入另做代表性只读验证。
- Test data rules: 使用模拟秘密标记和模拟数据完成隔离检查。
- 文档变更运行 constitution 治理检查，并依据用户要求人工复核；端到端测试逐项报告实际执行状态。

## Architecture Rules

- 业务插件经 dots_request 共享 macmini_gateway 的代理入口。
- 两个组件分别维护实现和测试，以 docs/CONTRACTS/ 为共同接口依据；通过现成通道协作。
- 认证适配与第三方目标配置归 macmini_gateway；客户端连接、响应消费与文件保存归 dots_request。
- 首版采用公司级基本连接认证。
- 常驻程序执行自动请求；Codex 辅助主动维护，本地服务专用权限保护秘密。

## Contract Rules

- 草案用于澄清；认证、写操作和文件传输相关问题确认后冻结接口。
- 认证字段由堡垒机生成，凭证发送目标由本地配置与校验结果确定。
- 上游业务响应及异常经过输出检查后返回，认证端点响应由本地适配器消费。

## Security And Safety Rules

- dots 通过结构化业务请求访问堡垒机；堡垒机的文件和程序由本地管理权限维护。
- 第三方秘密在堡垒机本地保存、读取和使用；对话、工具输出、日志、代码与测试材料采用业务字段或模拟内容。
- 第三方写操作在范围确认后实施；首次生产部署及真实凭证接入需明确目标和授权。
- 业务数据和文件按公司确认的范围上云。

## Dependency Rules

- 首版组件由现成通道、小型代理服务、本地配置及公共调用入口组成。

## Agent Rules

- 遵守 AGENTS.md 的授权边界，沿用已确认决定。
- 依赖条件待补齐时，继续独立可执行的文档及模拟验证，逐项报告状态。
- 分别记录本地测试、桌面 Codex、真实 dots 和脚本调用证据。

## Review Rules

- 分别检查范围符合度和验证证据。
- 候选、验证中、已通过和已部署状态按实际证据标注。
