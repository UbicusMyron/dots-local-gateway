# 001：轻量共享 API 基础设施边界

Last Reviewed: 2026-10-15

状态：架构边界已由用户确认；技术接入与写操作范围待定。

## Decisions

- 所有业务在 dots；本地堡垒机专门保存凭证、完成认证和请求/下载。
- 公司允许 API 数据及文件上云；第三方凭证保管和使用权限归属堡垒机本地服务。
- 文件系统和 Codex 构成双端主动维护入口。
- 自动请求由常驻程序执行，系统守护机制管理进程。
- dots 程序自主请求，并拥有业务循环。
- 公司基本连接认证直接适用于首版调用方。
- 首版交付公共调用入口、现成通道、小型代理服务和本地配置。
- 同一仓库包含 macmini_gateway 和 dots_request，分别部署于堡垒机和 dots；docs/CONTRACTS/ 维护共享契约。
- 两端分别通过模拟对端验证，再进行真实环境联合验收。

## Rationale

所有业务统一依赖凭证执行边界，复用平台认证和连接能力；实现规模与明确需求相称。

## Consequences

已认证调用方共享首版开放范围。未来新增权限需求按届时实际场景重新设计。
通道验收包括 AI 工具调用和脚本自主调用两条路径。
管理员通过 Codex 维护配置和程序，真实秘密通过堡垒机本地录入与服务权限管理。
