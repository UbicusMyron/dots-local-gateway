# SPEC

Last Reviewed: 2026-10-15

## Product Intent

为 dots 生产环境中的任意插件、skill 和脚本提供共享的第三方 API 调用能力。第三方凭证在公司本地堡垒机保管及使用；运营和云端通过业务接口获取数据与文件，公司允许这些结果上云。

## Users

- 运营：通过 dots/Codex 使用或开发业务插件。
- 管理员：通过堡垒机文件系统及 Codex 维护程序和配置，在本地录入凭证。

## Goals

- 业务代码自主循环和请求。
- 所有业务共用请求设施及第三方认证实现。
- 确定性常驻服务执行自动请求。

## Delivery Scope

- 文件系统和 Codex 提供双端维护入口。
- dots 承担业务算法、编排、脚本及循环；堡垒机承担结构化 API 请求与下载。
- 首版交付公共调用入口、现成通道、本地配置和常驻服务。
- 公司级连接认证适用于首版全部调用方。
- 业务数据及下载文件按业务需要进入云端。

## Core Workflows

1. Codex 理解业务意图，dots 中的插件或脚本产生结构化请求。
2. 公共调用入口发送服务别名、账户别名和业务请求参数。
3. 堡垒机验证公司调用方，在本地加入对应凭证，向配置的第三方发送请求。
4. 数据或下载结果交还 dots，由业务脚本处理。
5. 异常通过请求编号定位；结果待核实的操作先核对执行状态，再决定重试。

## Requirements

### Functional

- 统一请求入口支持服务和账户选择。
- 支持程序自主调用，循环和业务并发决策留在 dots。
- 支持第三方认证适配，包括按平台需要刷新 token。
- 支持 API 数据及文件下载；具体文件传输机制通过验证确定。
- 首版按公司调用方进行基本连接认证。

### Quality Requirements

- 第三方 key、client secret、refresh/access token 的保存、读取、认证交换和使用均在堡垒机本地完成。
- 公司调用凭证与第三方凭证分离；前者供 dots 使用。
- 服务持续运行，由系统守护机制负责启动和恢复。
- 返回值、日志、仓库和模型上下文使用业务字段、运行元数据及模拟测试材料。

## Constraints

- 堡垒机拟为 Mac mini；dots 为 OpenAI dots 云电脑。
- 优先验证 Secure MCP Tunnel，分别取得桌面 Codex、真实 dots 和脚本调用证据。
- 当前阶段为方案与文档，目标为生产环境使用。

## Acceptance Criteria

- 两个独立业务调用同一入口，第三方凭证与认证实现集中在堡垒机。
- dots 脚本自行循环发起模拟请求。
- 公司调用认证通过后执行请求；目标地址校验通过后加入第三方凭证。
- 模拟数据和模拟下载文件到达 dots，内容可核对。
- 正常、异常响应及日志通过模拟秘密隔离检查。

## Assumptions

- 首个验证使用模拟凭证、模拟数据和模拟 GET 接口。
- 首版以公司调用方身份为认证单位。

## Open Questions

- Q1 产品决定：首版第三方写入/修改范围待用户确认；该确认是相关功能实施的前置条件。
- Q2 技术验证：目标工作区的 dots 使用 Tunnel 私有 MCP 的能力，以及脚本自主调用路径。
- Q3 集成输入：首个真实平台、认证类型、代表性下载文件大小及耗时，在真实集成前收集；模拟验证可先行。
